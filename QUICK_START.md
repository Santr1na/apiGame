# 🚀 Быстрый старт с локальной базой данных

## Проблема
При использовании 4 разных API (RAWG, Giant Bomb, Steam, TheGamesDB):
- ❌ Медленные запросы (2-5 секунд)
- ❌ Лимиты API (20,000 запросов/день)
- ❌ Зависимость от внешних сервисов

## Решение: Локальная база данных SQLite

### ⚡ Преимущества
- ✅ **Скорость**: 10-50 мс вместо 2-5 секунд
- ✅ **Неограниченные запросы**: нет лимитов API
- ✅ **Офлайн работа**: не зависит от внешних API
- ✅ **Легко развернуть**: один файл `games.db`

---

## 📦 Установка (3 шага)

### 1. Установите зависимости
```bash
npm install
```

### 2. Заполните базу данных
```bash
npm run populate
```
⏱️ Займет 5-10 минут, загрузит ~800-1000 игр

### 3. Запустите сервер
```bash
npm run start:db
```

**Готово!** 🎉 Сервер работает на http://localhost:3002

---

## 🎮 Как это работает

### Без базы данных (старый способ):
```
Запрос → RAWG API (2 сек) → Giant Bomb API (1 сек) → Steam API (1 сек) → Ответ
Итого: ~4 секунды ⏱️
```

### С базой данных (новый способ):
```
Запрос → SQLite БД (20 мс) → Ответ
Итого: ~20 миллисекунд ⚡
```

### Гибридный режим (рекомендуется):
```
Запрос → Ищем в БД → Если нашли: возвращаем (20 мс)
                   → Если нет: запрос к API → сохраняем в БД → возвращаем
```

## ❓ FAQ

### Нужны ли API ключи?

**Для заполнения БД**: Да, нужны ключи RAWG, Giant Bomb, TheGamesDB  
**Для работы сервера**: Нет, если БД уже заполнена

### Как обновить игры в БД?

```bash
# Удалите старую БД и заполните заново
rm games.db
npm run populate
```

### Можно ли использовать другую БД?

Да! Вместо SQLite можно использовать:
- PostgreSQL (для больших объемов)
- MongoDB (для гибкой структуры)
- MySQL (для совместимости)

Но SQLite - самый простой вариант для старта.

### Сколько места занимает БД?

- 1,000 игр ≈ 2-5 MB
- 10,000 игр ≈ 20-50 MB
- 100,000 игр ≈ 200-500 MB
